# CaseClicker Unity Project Instructions

You are helping with a Unity C# game project called CaseClicker.

## Important project rules

- Prefer small, safe changes.
- Do not rewrite entire systems unless asked.
- Do not rename classes, files, serialized fields, prefab references, scene objects, or ScriptableObject fields without warning.
- Keep Unity Inspector references safe.
- Do not edit generated Unity/cache files.
- Do not edit Library, Temp, Logs, obj, Build, Builds, UserSettings, .csproj, .sln, or .slnx files.
- Search in Assets first.
- Project gameplay code should usually be inside Assets.
- Before big changes, make a short plan first and wait for approval.
- After editing code, check for likely Unity compile errors.
- Explain what files were changed and why.

## My current project focus

This is a CS2-style case/clicker game.

Important systems may include:
- Inventory
- Case opening
- Item rarity
- Item float values
- StatTrak
- Sorting and filtering
- Save/load
- UI panels and dropdowns
- Money/currency systems
- Upgrades and progression

## Coding style

- Use clear and simple C#.
- Avoid overcomplicated architecture.
- Keep MonoBehaviour scripts easy to connect in the Unity Inspector.
- Prefer readable code over clever code.
- Add comments only where they help explain non-obvious logic.

## Workflow

For big tasks:
1. Inspect only the relevant files.
2. Explain the current system briefly.
3. Make a plan.
4. Wait for approval before editing.

For small bug fixes:
1. Find the relevant script.
2. Fix the issue with minimal changes.
3. Explain the fix.
